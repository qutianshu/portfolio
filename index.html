独立项目 2026.09-至今 AI Workflow

一键生成行业/产品调研报告小助手

+

从 0 到 1 设计并落地一个 11 节点双迭代并行 Pipeline：输入一句话主题，自动完成检索、提炼、大纲、逐章撰写与邮件交付。

Dify DeepSeek-flash GPT-4o-mini Firecrawl SerpAPI 在线体验 →
pipeline.yml
问题：行业调研报告（如《中美 AI 行业报告》）人工撰写需大量检索、整理与成文，周期长、成本高；通用「单轮对话」直接生成，则上下文易污染、内容易失真、结果不可交付。
我的角色：从 0 到 1 独立完成产品设计与流程编排：节点拆解、模型选型、相关性过滤策略、结构化输出约定，并跑通验证（2026-09-14 全流程运行成功，邮件留痕）。
方案：11 节点双迭代并行 Pipeline（见上方节点图）：搜索 → 抓取 → 提炼 → 大纲 → 并行撰写 → 邮件交付。两处 ×10 并行迭代构成双层并行；DeepSeek-flash 承担批量粗活（提炼/撰写），GPT-4o-mini 负责结构化大纲。
结果：MVP 跑通即用：输入主题 → 自动检索 10 路网页 → 提炼过滤 → 生成大纲 → 10 路并行成章 → Markdown 全文邮件送达。已实际交付完整《中美 AI 行业报告》（2026-09-14 邮件留痕，见下方截图）。
方法论：① 模型成本分层：粗活/精活分模型，控制单次成本；② 双层并行：抓取与撰写均 ×10 并发，压缩串行长流程；③ 相关性过滤：无关网页输出空串，防止上下文污染；④ 结构化优先：用参数提取器取代 prompt 约定，输出稳定可复用。
被否决的方案：单轮长对话直出（上下文易污染、成本不可控）；自建爬虫（反爬与维护成本高）；全链路高配模型（质量收益有限但成本显著上升）。最终选择「开源平权模型干批量粗活 + 商用模型做结构化」的组合。
课程项目 AI 评测体系 汽车垂类

汽车垂类 · 内容识别与用户意向评测体系

+

面向「自动挂载汽车线索组件」的业务目标，从 0 设计一套可验收的评测资产：内容识别 / 信息抽取 36 条 + 用户意向识别 24 条，共 60 条正式用例，配套 8 维加权打分标准与双场景标注规范。

{ "is_auto_content": "是", "is_sales_related": "是", "vehicle_type": "新车", "brand": ["特斯拉", "AITO 问界"] … }
问题：汽车业务要支撑「自动挂载线索组件」：判断内容是否适合挂载、识别高意向用户、补齐新车/二手车/品牌/车系/车型字段。但模型输出缺少统一评测口径——好坏全凭感觉，无法验收、无法回归、无法定位 Bad Case。
我的角色：独立完成 PRD 与评测体系设计：把业务目标拆成「内容识别 + 用户意向」双任务，设计 8 维加权打分标准与双场景标注规范，构建 60 条正式用例（内容识别 36 + 用户意向 24），并给出验收口径与回归流程。
方案：内容识别 36 条覆盖新车测评/二手车/车型对比/资讯/技术科普/售后等场景，字段含 is_auto_content、is_sales_related、vehicle_type、brand、series、model，专项测试别名归一（问介→问界）、ASR 纠偏（领跑→零跑）、多实体抽取与内容主体变更；用户意向 24 条覆盖高/中/低/排除四类，含已提交线索、试驾导向、家庭共决策、从业者干扰、车展围观等边界样本。打分标准 8 维加权：字段准确性 25% 权重最高，任务遵循 10%、完整性 15%、标准化一致性 15%、边界不乱猜 10%、鲁棒性 10%、多源证据融合 10%、业务可用性 5%。
结果：交付可复用的评测资产：60 条正式用例 + 双场景标注规范 + 8 维打分标准 + 汇总看板，支撑离线评估、版本回归、灰度前验收与 Bad Case 回流；验收口径明确——内容识别看汽车内容 Precision、购车/卖车相关 Precision、品牌/车系/车型准确率与字段完整度，用户意向识别看高意向 Precision、Recall 与 Macro-F1。
方法论：① 目标反推用例：先定「是否挂载 / 是否线索」的业务决策，再定评测维度与用例；② 样本结构 4:3:3（正/负/边界），避免全低难度失真；③ 权重对齐业务：字段准确性 25% 最高，格式规范仅 10%；④ 标注规范先行：别名、边界、口径先写死，评测结果才可复现、可归因。
